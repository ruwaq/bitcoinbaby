## Detalle técnico de cada Fix

### Fix #1 — Tests BIP-340/341/86 + init de noble hashes

**Bug real encontrado (no estaba en el reporte):**
`packages/bitcoin/src/crypto.ts:signSchnorr` usaba `secp256k1.schnorr.sign(message, privateKey)` (sync) de `@noble/secp256k1` v3.0.0. Esta versión requiere configurar manualmente:

```ts
secp256k1.hashes.sha256 = nobleSha256;          // DIRECTAMENTE la función, no {sync:...}
secp256k1.hashes.hmacSha256 = (key, ...msgs) => {...};
```

Sin esto, cualquier llamada a `signSchnorr`/`verifySchnorr` lanza `Error: hashes.sha256 not set`. **Esto impedía firmar TXs Taproot en producción**. (Las variantes async usan WebCrypto internamente y no necesitan esto.)

**Verificación del fix:** El código de `createTweakedSigner` en `wallet.ts:356-433` y `transactions/builder.ts:860-922` YA ES CORRECTO según BIP-340/341/86. La diferencia entre ambas (`wallet.ts` tiene una negación redundante post-tweak) es inofensiva — tiny-secp256k1 maneja la negación internamente en `signSchnorr`.

**Archivos:**

- `packages/bitcoin/src/crypto.ts` (+29 líneas, fix producción)
- `packages/bitcoin/tests/bip340-schnorr.test.ts` (12 tests, vectores canónicos BIP-340)
- `packages/bitcoin/tests/bip86-vectors.test.ts` (6 tests, vector canónico BIP-86)
- `packages/bitcoin/tests/bip341-keypath-spend.test.ts` (4 tests, key-path spend Y-par e Y-impar)

**Lección TDD:** Al principio inventé valores de vectores BIP-340/86. Los tests fallaban por datos incorrectos, no por código incorrecto. Los reescribí usando los valores oficiales del CSV de bips/bip-0340 y de la spec BIP-86.

### Fix #4 — Treasury Signer Schnorr signing

**Bug grave confirmado:** `treasury-signer.ts:signSpell` tenía un `TODO: Implement PSBT signing if prover returns unsigned transactions` explícito. El flujo era:

```ts
// ANTES (roto):
const proverResponse = await this.prover.prove(spell);
return {
  commitTxHex: proverResponse.commitTx, // ← sin firmar!
  spellTxHex: proverResponse.spellTx, // ← sin firmar!
};
```

Emitir estas TXs al mempool fallaría con `mandatory-script-verify-flag-failed`.

**Fix implementado:**

```ts
// DESPUÉS (correcto):
const proverResponse = await this.prover.prove(spell);

// 1. Sign commit TX (input spends funding UTXO)
const signedCommitHex = await this.signProverTx(
  proverResponse.commitTx,
  fundingUtxo,
);

// 2. Sign spell TX (input spends commit TX output 0, also treasury Taproot)
const unsignedCommitTx = bitcoin.Transaction.fromHex(proverResponse.commitTx);
const commitTxid = unsignedCommitTx.getId();
const spellFundingUtxo = {
  txid: commitTxid,
  vout: 0,
  value: unsignedCommitTx.outs[0]?.value ?? 0,
};
const signedSpellHex = await this.signProverTx(
  proverResponse.spellTx,
  spellFundingUtxo,
);
```

`signProverTx` usa helpers existentes: `rawTxToPsbt()` (convierte hex→PSBT, poblando witnessUtxo via BlockchainAPI) → `wallet.signAndFinalizePSBT()` (firma Schnorr BIP-340/341 con key negation interna).

**Dependency Injection introducida:**

```ts
export interface SignerDeps {
  prover?: Pick<CharmsProverClient, "prove">;
  blockchain?: BlockchainAPI;
}

constructor(config: SignerConfig, deps?: SignerDeps) {
  // production: deps=undefined → instancia CharmsProverClient + MempoolClient reales
  // tests: deps={prover: mockProver, blockchain: mockBlockchain}
}
```

**Test nuevo:** `packages/bitcoin/tests/signer/treasury-signer.test.ts` (5 tests). Construye TXs reales (con bitcoinjs) que simulan la respuesta del prover + mock de BlockchainAPI que devuelve prevTx hex.

**Pitfall encontrado y resuelto:** Calculé `commitTxid` después de firmar (de `signedCommitHex`), obteniendo un txid distinto al esperado. Lo corregí computándolo del TX **sin firmar** (`proverResponse.commitTx`). El txid de SegWit NO cambia al firmar, pero usar el unsigned es más claro y no requiere re-parseo.
